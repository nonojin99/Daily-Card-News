## ⏰ 무인 자동 실행 절차 — 매일 06:00 KST (2026-10-18~, 이 절을 먼저 읽을 것)

매일 새벽 예약 세션이 **사람 없이** 끝까지 돈다. 아래 순서를 건너뛰지 않는다. 세부 기준은 각 절에 있고, 충돌하면 각 절이 이긴다.

1. **준비** — `TZ=Asia/Seoul date` 로 날짜·요일 확인 → 어제 메인·지난주 같은 요일 서브 브리프의 tracker 를 읽는다.
2. **리서치** — 메인·서브 리서치 에이전트 2개 동시(WebSearch 발견 → WebFetch 본문 검증, Firecrawl 금지).
3. **작성** — 어제 `<style>` 복사, 카드마다 `.cn` 블록(`cn-t`·`cn-s` + 그림 재료), 낭독 원고, 메인은 서울 날씨 한 줄.
   서브·롱리드는 **모든 카드에 개념도(`cn-v`)·도표·허용 이미지** 중 하나(글자 타일 금지 — '카드 이미지·그림 개선 규칙').
4. **브리프 검토 하네스** — 독립 검증 에이전트가 체크리스트 1~16 판정 → FAIL 수정.
5. **카드 검토 하네스 2단계** ('카드 검토 하네스' 절) — 메인·서브 둘 다:
   ① `python3 tools/check_cards.py <브리프>` + `node tools/render_cards.js <브리프> <폴더>` (규칙·넘침, 종료 코드 1 이면 FAIL)
   ② 독립 에이전트가 PNG 를 직접 보고 규칙·전문성·가독성·흐름 판정 → FAIL 이면 고치고 ①부터 다시(최대 3회).
   ③ 통과하면 판정 요약을 `/tmp/card-review/<브리프 이름>.stage2.md` 에 쓴다.
   **push 관문**: `.claude/settings.json` 훅이 `git push` 직전에 `tools/prepush_gate.py` 로 ①을 다시 돌리고 ③ 기록(브리프보다 나중에 쓴 것)을 확인 —
   없거나 FAIL 이면 push 가 막힌다. 루틴 프롬프트와 별개로 저장소의 `CLAUDE.md` 가 세션 시작 때 자동으로 읽혀 이 절차를 알린다.
6. **발행** — 오늘 브리프 HTML 2개만 `git add` → main 에 직접 push(07:00 전 목표). 막히면 Drive 발행함.
   **인스타 게시일(월·화·금·토·일)** 은 캡션 2개 + `publish/request.json`(캐러셀 + 오디오 릴스)도 같은 커밋에 넣는다 → push 뒤 자동 등록('인스타그램 운영 → API 게시').
7. **push 뒤는 Actions 가 자동** — manifest·이미지 보존·MP3·AI 일러스트·**인스타 카드 JPG·오디오 릴스 MP4**, 게시일엔 인스타 등록까지. 카드 JPG 는 브리프나 렌더러(`app/cards.html`)가 바뀌면
   **스스로 다시 굽는다**(`cards/…/source.sha1` 지문 비교). 그러니 **카드를 고쳐 다시 push 하는 것만으로 충분하다.**
8. **보고** — 다룬 항목·제외 이유·검토 FAIL 수정 내역·**카드 검토 1단계 FAIL/WARN 수와 2단계 반복 횟수**·날씨·원고 분량·발행 경로.
   **끝날 때마다 한 줄 요약 알림**을 보낸다(2026-10-24~, Slack 으로 받음 — CLAUDE.md '매일 Slack 요약'). 실패(발행 실패, 검토 3회 FAIL 등)는 첫 줄에 ⚠.

**무인 실행 환경에서 알아 둘 것**
- Build manifest 워크플로는 **한 번에 하나만** 돌고(concurrency), 커밋 push 가 밀리면 rebase 후 3번까지 다시 시도한다 — 발행 push 와 겹쳐도 카드·MP3 커밋이 사라지지 않는다.
- **Actions 를 세션에서 실행할 수 없다**(workflow_dispatch → 403 "Resource not accessible by integration"). Run workflow 가 필요한 일을 만들지 말고, push 로 끝나게 한다.
- 렌더 도구(`tools/render_cards.js`)는 **실행할 때마다 자기 로컬 서버를 띄웠다 닫는다** — 따로 `http.server` 를 띄우지 않는다(백그라운드 서버는 시간 제한으로 죽는다).
  Playwright 는 전역 설치(`npm root -g`)를 자동으로 찾고, 브라우저는 `/opt/pw-browsers/chromium` 을 쓴다. `playwright install` 금지.
- ESA 이미지 호스트는 작성 환경에서 막혀 있다 → 렌더 도구가 "이미지 자리" 안내 그림을 넣는다. 그날 카드의 실제 이미지는 push 뒤 Actions 가 굽는다.
  **다음 날 세션은 어제 `cards/…/` JPG 를 열어 이미지가 제대로 들어갔는지 한 번 확인**하고, 문제가 있으면 브리프·렌더러를 고쳐 push 한다(자동으로 다시 구워진다).
- 이미 인스타에 **게시된** 카드는 다시 구워도 게시물은 바뀌지 않는다. 게시 뒤 오류는 README '인스타그램 운영'의 24시간 정정 규칙을 따른다.

## 제작 파이프라인 — "하네스" 구조

```
리서치 하네스 (Haiku)   →  분야별 정보 수집·요약
편집자 하네스 (Haiku)   →  검수·팩트체크·분량 조정
마케팅 하네스 (Sonnet)  →  "마케터의 시선" 인사이트 부착
디자인 하네스 (Sonnet)  →  카드뉴스 HTML 렌더링
검토 하네스 (Sonnet)   →  발행 전 최종 검증 (아래 체크리스트 통과)
```

> **검토 하네스의 한계 (정직하게)**: 이 단계는 별도의 독립된 검토자가 아니라,
> 같은 작업 세션이 발행 직전에 한 번 더 자기 결과를 점검하는 '강제 통과 관문'이다.
> 완전한 제3자 검토는 아니지만, 정합성·날짜·반복 같은 기계적 오류는 대부분 여기서 걸러진다.
> 특히 중요한 발행은 완성본을 새 대화에 붙여넣어 별도로 검토받는 것을 권장한다.

### 발행 전 검증 체크리스트 (검토 하네스)

브리프를 내보내기 전, 아래를 하나씩 통과시킨다. 하나라도 걸리면 고치기 전엔 발행하지 않는다.

1. **숫자 정합성** — 표·목록의 항목 수가 라벨과 맞나?
   (예: 토너먼트 라운드별 경기 수 — 16강=8경기, 8강=4경기, 4강=2경기. "8강인데 10팀" 같은 모순 금지)
2. **라운드·단계 표기** — 대회 진행 단계를 정확히 불렀나?
   (48개국 월드컵은 32강부터 토너먼트. 한 단계씩 밀려 부르지 않았는지 확인)
3. **날짜 최신성** — 모든 항목이 오늘 기준인가? 오래된 뉴스를 새것처럼 넣지 않았나?
4. **반복 필터** — 어제 카드와 실질적으로 겹치나? 변화가 있을 때만 재등장했나?
5. **한 사건 3카드** — 한 사건이 카드 3개를 넘지 않나?
6. **재난·민감 톤** — 참사·부고에 절제된 톤인가? 마케팅 인사이트가 부적절하지 않나?
7. **추측 금지** — 확인 안 된 수치·이름·라인업을 지어내지 않았나? 불확실하면 뺐나?
8. **변동 정보 경고** — 가격·환율·일정 등에 "⚠ 변동 가능" 표기를 했나?
9. **파일명 규칙** — `YYYY-MM-DD_{type}-brief.html` 형식이 정확한가?
10. **출처 링크 품질** — 모든 출처가 **기사 본문 URL**인가?
    (언론사 홈페이지·위키·블로그 링크 금지 · 같은 URL을 3개 이상 카드에 재사용 금지 · 위키/블로그는 언론사 원출처로 대체)
11. **요일 표기 검증** — 파일명의 날짜와 본문의 요일이 실제로 일치하는가? (`date` 명령으로 대조)
12. **도표 정합성** — 차트·스테퍼가 있다면:
    - 도표에 쓰인 값이 **전부 같은 카드의 본문·스펙 표에도 있는가?** (그림에만 있는 값 = 검증 불가 = 금지)
    - 도형 좌표를 **수치에서 계산**했는가? 눈대중으로 그린 막대 길이 금지.
    - **이중축을 쓰지 않았는가?** 단위·자릿수가 다른 두 계열은 지수화해 한 축에 올린다.
    - 출처에 없는 값을 그리지 않았는가? (예: 시각이 보도되지 않은 득점)
    - **렌더링해서 눈으로 봤는가?** 390px·820px 두 폭에서 텍스트 넘침·라벨 겹침 확인.
    - **도표가 없다면** — 메인에 비교 가능한 수치 카드가 있는데 도표가 0개는 아닌가? footer 에 검토한 카드와 생략 사유를 구체적으로 적었는가?
13. **공공 이미지 · 그림 우선순위** — 과학 브리프에 **실제 사진이 1장 이상 있는가**(없으면 시도·이유가 보고에 있는가)? 사진 없는 카드에 AI 개념도(`cn-img`)가 있는가(도표만 낸 카드는 FAIL)? 크레디트가 짧아 출처 장이 넘치지 않는가? 이미지가 있다면:
    - 호스트가 `cdn.esawebb.org` / `cdn.esahubble.org` 중 하나인가? URL 이 `/screen/` 크기인가?
    - 크레디트가 **이미지 페이지의 Credit 원문과 한 글자까지 같은가?** 이미지 페이지로 링크되는가?
    - `src` 와 `data-remote` 가 같은 URL 인가?
    - 이미지가 없어도 캡션만으로 내용이 전달되는가?

14. **낭독 원고** — `<details class="audio-script">` 가 있다면:
    - 원고의 모든 사실·숫자가 **같은 브리프 카드 본문·스펙 표에 있는가?** (원고에서 새 사실 금지)
    - 숫자는 반올림만 했는가? 매체별로 엇갈리는 수치는 범위·"여러 명"처럼 말했는가?
    - 재난·참사 카드는 담담한 톤인가? '마케터의 시선'을 읽지 않았는가?
    - 분량이 브리프 종류별 기준(아래 '오디오' 절) 안인가? 여행·액티비티는 1분 소개인가?
15. **서울 날씨 한 줄** (메인만) — `<p class="weather">` 가 있다면:
    - 출처가 **오늘 아침(또는 전날 저녁) 발행된 날씨 기사 본문**이고, 그 기사에 **서울** 최저·최고기온·강수가 실제로 있는가?
    - 숫자·강수 시간대가 기사와 같은가? 기사에 없는 값(강수확률 등)을 지어 넣지 않았는가?
    - "⚠ 변동 가능" 표기와 출처 링크가 있는가? 낭독 원고 끝의 날씨 문단이 이 한 줄과 같은 내용인가?

16. **카드 넘겨보기** (메인) — 카드마다 `<div class="cn" hidden>` 이 있다면:
    - `.cn-t`·`.cn-s` 의 사실·숫자가 **같은 카드 본문·스펙 표에 있는가?** (카드용 문장에서 새 사실 금지)
    - `.cn-t` 는 2줄(줄마다 14자 안팎), `.cn-s` 는 해요체 2~3문장(공백 포함 70~100자)인가?
    - **카드 검토 하네스 1·2단계를 모두 통과했는가?** (아래 '카드 검토 하네스' 절)
    - **글자 타일 카드가 없는가?** (서브 브리프·롱리드는 모든 카드에 `cn-v` 또는 허용 이미지) · **큰 숫자가 제목과 같은 값이 아닌가?** · **`.topic` 이 분류어(발견·결과·전망 등)가 아닌가?** (위 '카드 이미지·그림 개선 규칙')
    - `svg.cn-v` 가 있다면 12번 도표 규칙(값은 카드에 있는 것만, 좌표는 수치에서 계산)을 지켰는가? 재난·참사 카드는 담담한 그림(시간 순서·단계)인가?

## 큐레이션 규칙

수 주간의 운영을 거치며 확립된 규칙입니다.

1. **화제성 우선** — 억지로 모든 분야를 채우지 않는다. 약한 분야는 과감히 제외.
2. **한 사건당 최대 3개 카드** — 빅이슈라도 갈래는 3개에서 끊는다.
3. **지속 정보는 변화가 있을 때만 재등장** — 전시·축제·시즌 정보는 종료 임박, 연장, 매진 등 새 변화가 있을 때만 다시 다룬다. 어제와 동일한 내용의 반복 금지.
4. **광범위 스캔 먼저** — 추적 중인 스토리에 매몰되지 말고, 매일 일반 뉴스를 넓게 훑어 새 대형 사건(재난 등)을 놓치지 않는다. 스캔은 "주요 뉴스+날짜" 검색보다 **주요 언론사 첫 화면을 직접 fetch**(연합뉴스·경향 등 1~2곳)하는 방식을 우선한다 — 검색은 오래된 기사가 섞여 나온다.
5. **오래된 뉴스를 새것처럼 다루지 않는다** — 날짜 확인이 안 되면 넣지 않는다.
6. **이미지·위성사진은 검증된 출처만** — 재난 이미지는 오정보가 흔하므로 Maxar Open Data, NASA Earth Observatory, Copernicus EMS 등 공식 출처만 신뢰.
7. **재난·참사에는 절제된 톤** — 마케팅 인사이트도 "침묵할 줄 아는 것"을 원칙으로.
8. **변동 정보에는 경고 표기** — 가격·일정·환율 등은 "⚠ 변동 가능, 링크 확인"을 명시.

### 시각화 (2026.10.01~)

**사진은 쓰지 않는다.** 언론사 보도사진은 저작권이 있고, 핫링크는 차단·링크 깨짐으로 무너지며,
무인 실행에서는 매일 라이선스를 확인해 줄 사람이 없다. 대신 **직접 생성하는 인라인 SVG**만 쓴다.

- **적용 대상**: 수치 또는 절차 단계가 있는 카드만. 억지로 모든 카드에 넣지 않는다(큐레이션 규칙 1과 같은 원칙).
- **최소 기준 (2026.10.17~)**: "억지로 넣지 않는다"가 "안 넣어도 된다"로 읽혀 10/14~10/16 브리프 6개에 도표가 0개였다. 그래서 하한을 둔다.
  - **메인 브리프**: 비교 가능한 수치가 2개 이상인 카드(증시 종가·등락률·수급, 물가 전월·당월, 순위·누적 기록 등)가 하나라도 있으면 **도표 최소 1개**.
  - **서브 브리프**: 수치·일정 비교(순위, 기록, 거리, 운영 시간 등)가 있는 카드가 있으면 **1개 권장**.
  - 넣지 않았다면 footer 📊 줄에 **검토한 카드와 생략 사유**를 쓴다("도표가 필요한 수치 흐름이 없음" 같은 일반 문구 금지).
  - 자주 쓰는 형태: 가로 막대(비교) · 가운데 0 막대(순매수/순매도) · 3~5점 꺾은선(며칠간 종가) · 시간 막대(운영 시간) · 스테퍼(절차·연표).
- **차트 계열색은 브리프 액센트와 분리한다.** 액센트 `#3d5a4c` 는 채도 0.042 라 데이터 색으로 쓰면
  회색으로 읽힌다. 집 팔레트 조합도 색각 검증을 통과하지 못했다(그린+테라코타 protan ΔE 2.6).
  **차트 전용: `--s1:#2f6d9e` / `--s2:#c06a24`** — 명도대역·채도하한·색각분리(protan ΔE 18.9,
  tritan 26.2)·정상시야(ΔE 25.3)·대비 전 항목 통과. 매일 이 두 색을 그대로 재사용한다.
- **상태색은 계열색을 쓰지 않는다.** 스테퍼(단계 표시)는 액센트 + 회색 `#cfcdc4` 로만.
  계열색을 상태에 재사용하면 "주황 = 전년동월비"와 "주황 = 현재 단계"가 한 브리프에서 충돌한다.
- **이중축 금지.** 단위·자릿수가 다른 두 계열(코스피 6,889 vs 코스닥 846)을 한 그림에 두 축으로
  그리면 없는 상관이 만들어진다. **기준일 = 100 으로 지수화해 한 축에** 올린다.
- **모르는 값은 그리지 않는다.** 출처 기사에 없는 시각·위치·배치는 추측해서 그리지 않는다.
- **그림이 유일한 전달 수단인 값은 두지 않는다.** 도표의 모든 값은 같은 카드의 스펙 표에도 있어야
  한다. 스펙 표가 곧 대체 텍스트 역할을 한다.
- **마크 규격**: 막대 24px 이하 · 데이터 끝만 4px 라운드(높이가 작으면 `r = min(4, h/2)` 로 클램프) ·
  선 2px · 점 반지름 4 이상 + 2px 면색 링 · 격자는 실선 헤어라인(점선 금지) ·
  **값·라벨은 텍스트 토큰으로**(계열색으로 글씨를 칠하지 않는다).
- **SVG 안 텍스트는 짧게.** viewBox 와 함께 축소되므로 긴 설명은 HTML `.cv-note` 에 쓴다.
  좁은 화면(560px 이하)에서는 user unit 을 키워 화면상 크기를 유지한다.
- **JS·다크모드는 넣지 않는다.** 이 저장소는 JS 0줄로 운영된다. 툴팁 대신 스펙 표가 값을 보장한다.
- **CSS 블록은 어제 파일에서 그대로 복사한다**(디자인 드리프트 방지 — 기존 규칙과 동일).

### 공공 이미지 — 과학 브리프 한정 (2026.10.01~)

뉴스 사진은 여전히 쓰지 않는다. **일요일 우주·과학 브리프에서만**, 라이선스를 이미지 페이지에서
직접 확인할 수 있는 출처의 이미지를 쓴다. 천문 주제가 아닌 주(지질·생물 등)에는 넣지 않는다.

**허용 출처 — 이 두 곳뿐** (이미지 파일 호스트 기준)

| 호스트 | 기관 | 라이선스 | 크레디트 |
|---|---|---|---|
| `cdn.esawebb.org` | ESA/Webb | CC BY 4.0 | 이미지 페이지의 Credit 줄 원문 그대로 |
| `cdn.esahubble.org` | ESA/Hubble | CC BY 4.0 | 이미지 페이지의 Credit 줄 원문 그대로 (Acknowledgement 줄 포함) |

- **포토코리아(한국관광공사)는 2026.10.01 검토 후 제외.** 사진마다 공공누리 유형이 다르고(1~4유형, 일부 사용불가),
  목록 페이지는 WebFetch 403, 관광사진 API(apis.data.go.kr)·이미지 서버(tong.visitkorea.or.kr)는 작성 환경에서
  네트워크 정책 차단이라 **사진별 유형을 무인 실행이 확인할 수 없다.** data.go.kr 인증키 발급 + 네트워크 허용이
  생기면 재검토(API 데이터셋은 공공누리 1유형으로 안내됨, 출처표시 형식 "ⓒ한국관광공사 포토코리아-촬영자").
- **NASA 이미지 라이브러리(images.nasa.gov)는 넣지 않았다.** 퍼블릭 도메인이 원칙이지만 페이지가
  JS 로 그려져 WebFetch 로 크레디트·제3자 표시를 확인할 수 없다. **APOD 는 개인 사진가 저작물이 많아 금지.**
- **크기는 반드시 `/archives/images/screen/` URL** (약 400KB). 같은 이미지의 large JPEG 는 286MB 인
  사례가 있다. Actions 스크립트에도 8MB 상한이 있지만 애초에 screen 을 쓴다.
- **CC BY 4.0 조건**: 크레디트를 **한 글자도 바꾸지 않고**, **이미지에서 떼어놓지 않고**(캡션 바로 아래),
  **링크가 살아 있게**(이미지 페이지로 연결) 표기한다. 로고는 CC BY 대상이 아니므로 쓰지 않는다.
- **확인 실패 = 제외.** 이미지 페이지를 WebFetch 로 열어 제목·공개일·Credit 원문을 확인하지 못하면
  이미지를 넣지 않는다. 추측한 크레디트로 넣지 않는다.
- **캡션이 본체, 사진은 보조.** 이미지가 깨져도 캡션만으로 무엇을 보여주려 했는지 전달돼야 한다.
  `alt` 에는 이미지에 보이는 것을 문장으로 쓴다.

**동작 방식 — 핫링크 + Actions 보존**

1. 브리프 작성 시 `src` 와 `data-remote` 에 **같은 원격 URL** 을 넣는다 → 발행 즉시 독자 브라우저가 원격에서 불러온다.
2. push 하면 Actions(`.github/scripts/localize_images.py`)가 허용 호스트의 이미지만 `img/<날짜>/` 로 내려받고
   `src` 를 로컬 경로로 바꿔 커밋한다(`[skip ci]`). `data-remote` 는 출처 추적용으로 남는다.
3. 다운로드가 실패하면 그 이미지는 건드리지 않는다 → 핫링크로 계속 보인다. 빌드는 실패하지 않는다.

> 작성 환경(클라우드)에서는 NASA·ESA 호스트가 네트워크 정책으로 차단돼 이미지 파일을 직접 받을 수 없다.
> 그래서 다운로드를 GitHub Actions 에 맡긴다. 브리프 월별 폴더 정리 시 `img/` 도 함께 옮길 것.

**마크업** (카드의 `<h2>` 바로 아래)

```html
<figure class="photo">
```

#### 카드 이미지·그림 개선 규칙 (2026-10-18 추가 — 과학 카드 검토에서 나온 지적 반영)

2026-10-18 과학 카드 8장을 눈으로 검토해 나온 문제와 규칙이다. **이 절이 위쪽 '카드 넘겨보기' 절과 충돌하면 이 절을 따른다.**

1. **공공 이미지는 카드에도 쓴다.** 브리프에 `figure.photo` 가 있으면 카드 위쪽 그림이 된다(도표 `figure.chart`·`cn-v` 다음, 정보 그림보다 먼저).
   허용 호스트·`/screen/` 크기·`data-remote` 가 맞을 때만 그리며, **크레디트는 이미지 위에 같은 그림 안에 붙고**(CC BY) 마지막 출처 장에도 다시 적힌다.
   이미지가 2023년 관측 같은 **다른 연구의 자료면 캡션에 그 사실을 적는다**(이번 논문 이미지로 오인 금지).
   카드에서는 이미지를 가리지 않게 **이미지 아래 띠**에 설명·크레디트를 둔다. 설명은 `<figure class="photo" data-card-cap="2023년 웹 관측 · 구름 속 석영의 흔적">`
   처럼 **무슨 그림인지 한 줄**(20자 안팎, 값은 카드 본문에 있는 것만)로 적는다. 이미지가 말하는 것과 **카드 제목이 같은 이야기**여야 한다
   (석영 구름 그래프 + 제목 "밀도가 낮은 행성" ✗ → "밀도는 목성의 6~14%, 구름엔 석영 입자" ✓).
2. **대학·연구기관 보도자료 이미지는 쓰지 않는다.** 2026-10-18 점검: 브리스톨대 WASP-17b 보도자료의 지도·일러스트 2장은 크레디트가
   "Engine House and Hannah Wakeford", 페이지 하단 "Copyright © University of Bristol. All rights reserved.", **이미지별 라이선스 표기 없음** → 사용 불가.

   ② 기관의 **서면 허가**가 있어야 한다(허가 문의는 사용자가 한다). 확인 못 하면 넣지 않는다. 대신 아래 3번의 개념도를 그린다.
3. **글자 타일 금지.** 렌더러 안전망도 바꿨다 — 그림 재료가 하나도 없으면 분야 글자 대신 **카드 스펙 표 앞 3줄을 정보 시트**로 보여 준다
   (제목·요약에 없는 세부라 반복이 아니다). 그래도 이것은 최후 수단이고, 작성 단계에서 그림을 준비한다. 그림 재료가 없어 분야 글자("관측 기법" 등)만 큰 타일로 나오는 카드를 만들지 않는다. 서브 브리프·롱리드는 **모든 카드에 `svg.cn-v`** 를 쓴다.
   - 원리·방법·원인을 보여 주는 **개념도**(전/후 비교, 흐름, 단계). 왼쪽 '기존', 오른쪽 '새 방식'처럼 **한 장면에 비교 하나**.
   - 개념도에는 수치를 그리지 않는다. 모양을 과장했거나 칸 수가 예시면 그림 안에 **"개념도 · 모양은 과장"** 을 적는다.
   - 연구진의 계획·전망은 단계 그림으로 그리되 **"연구진의 계획 · 확인된 결과 아님"** 을 적는다.
   - **개념도의 품질 기준 — "왜·어떻게"가 그림에 보여야 한다.** 동그라미 몇 개에 글자를 붙인 것은 개념도가 아니다.
     원리 카드는 **위치 관계**(예: 항성–행성–망원경, 낮·밤, 바람 방향)를, 결과 카드는 **기준 대비 차이**(예: 점선 '기존 가정' 위에 실제 모양)를,
     선행 연구 카드는 **연구 흐름 타임라인**을 그린다. 같은 브리프 안에서 같은 구도(좌우 비교 등)를 두 번 쓰지 않는다.

   - 큰 숫자가 암호처럼 읽히는 값(예: "18.7°" 하나만 덩그러니)은 큰 숫자로 쓰지 말고 타임라인·개념도의 보조 글자로 넣는다.
4. **같은 말을 두 번 쓰지 않는다.** 카드 위 큰 숫자·그림이 제목과 같은 값이면 안 쓴다(제목 "밀도가 목성의 6~14%" + 큰 숫자 "6~14%" 중복 사례).

5. **`.topic` 태그는 구체적인 말로.** "발견·결과·전망·관측 기법·대상 행성·선행 연구" 같은 **분류어 금지** — 카드 제목 위에 붙는 라벨이라 정보가 없다.
   그 카드만의 핵심어를 **2~8자**로 쓴다(좋은 예: "둥근 가정", "부푼 행성", "가장자리 쪼개기", "아침과 저녁", "날씨 지도").

   - 표지: 렌더러가 파일명으로 분야 칩을 크게 넣는다 — daily "오늘의 뉴스" · ai "AI·테크" · sports "스포츠" · culture "문화" · music "음악" · travel "여행" ·
     activity "주말 액티비티" · science "우주·과학" · 묶음은 "이번 주 숫자"·"주말 뭐하지". 카드 바닥글에도 같은 분야 이름이 들어간다. 새 종류를 만들면 `app/cards.html` 의 `CAT` 표에 추가.
   - 인스타 캡션 **첫 줄은 `[분야]` 로 시작**한다(예: `[우주·과학] 외계행성 대기는 동그란 원이 아니었다 …`). 해시태그에도 분야어를 하나 넣는다.

#### 카드 그림 우선순위 — ① 실제 이미지 → ② AI 일러스트 → ③ 개념도 (2026-10-21 사용자 결정)

"내용은 좋은데 도형이 너무 형식적"이라는 피드백(10/21 문화 카드)으로 정했다. **이 절이 위 절들과 충돌하면 이 절을 따른다.** 렌더러(`app/cards.html` `visualOf`)도 이 순서다.

1. **① 실제 그림·사진 — 라이선스가 명시된 것만** (`figure.photo`, 브리프 본문·카드 둘 다)
   - **출처 표시만으로는 저작권 문제가 해결되지 않는다.** 출처 표시는 라이선스가 허락한 경우의 *조건*일 뿐, 허락 자체가 아니다.
     그래서 **포스터·보도사진·영화 스틸·앨범 커버·공연 사진·작가의 작품 사진은 출처를 적어도 쓰지 않는다**(배급사·소속사·작가의 서면 허가가 있을 때만 — 허가 요청은 사용자가 한다).
   - 허용 출처 (이미지 **페이지**를 WebFetch 로 열어 라이선스를 확인한 것만):

     | 호스트 | 라이선스 | 크레디트 형식 |
     |---|---|---|
     | `cdn.esawebb.org` · `cdn.esahubble.org` (`/screen/`) | CC BY 4.0 | 페이지의 Credit 원문 그대로 |
     | `upload.wikimedia.org/wikipedia/commons/` | 파일 페이지(`commons.wikimedia.org/wiki/File:…`)의 **퍼블릭 도메인·CC0·CC BY·CC BY-SA** | `작가 · 라이선스(예: CC BY-SA 4.0) · Wikimedia Commons` + 파일 페이지 링크 |

   - **정책브리핑(korea.kr) 사진은 쓰지 않는다 (2026-10-25 확인).** 저작권 정책(`korea.kr/guide/copyRight.do`) 원문: 사진은 "정부기관 및 연합뉴스 등에 저작권이 있으며, 이미지의 경우, 통로이미지(주)에 저작권",
     "공공누리가 부착되지 않은 자료 및 부착 되었더라도 사진 및 이미지를 사용하고자 할 경우에는 … 각 메뉴 담당자와 사전에 협의한 이후 이용" — 공공누리 1유형은 **텍스트에만** 적용된다. 무인 루틴은 사전 협의를 할 수 없으므로 제외(사람이 협의해 허락을 받으면 그 사진만 예외).
   - Commons 에서 쓰지 않는 것: **"미국에서만 퍼블릭 도메인"**(PD-US 등 한국 보호기간 미확인), 라이선스 틀이 없거나 "저작권 주장"·삭제 토론 중인 파일,
     **살아 있는 인물이 주인공인 사진**(초상·퍼블리시티권), 포스터·앨범 커버·로고(Commons 에 있어도 대부분 비자유 파일).
   - 쓸 만한 예: 작가 사후 70년이 지난 작품(김홍도·정선 등 옛 그림, 고전 회화), 클래식 작곡가 초상(옛 그림·사진), 공연장·미술관 건물 사진(CC BY/BY-SA), 천체 사진(ESA).
   - **문화 브리프는 "작품 대신 실제 장소·현장"** (2026-10-21 첫 적용): 전시가 열리는 미술관 건물, 공연장, 시상이 열린 영화제 현장(그해 사진이면 더 좋다).
     AI 그림은 실제 장소와 달라 괴리가 생기므로 **실제 장소·행사 현장을 그린 것처럼 보이는 AI 장면은 쓰지 않는다**(라이선스 사진이 있으면 그 사진, 없으면 ③).
     대신 **작품의 내용·주제를 보여 주는 장면**(줄거리의 상황, 매체·재료, 원작→무대 같은 변화)은 AI 로 그린다 — 카드에 'AI 생성 이미지'가 표시되고, 실존 인물·작품·포스터는 재현하지 않는다.
     (2026-10-21 사용자 판단: 린 허쉬만 리슨 '모니터 벽'·서세옥·서도호 '한옥과 모형'·실낙원·남벌은 AI, 서소문본관·로카르노는 실제 사진이 낫다.)
     장면이 기사에 없는 사실을 만들지 않게 한다 — 예: 초분은 기사에 '새아버지가 다루는 장례문화'로만 나오므로 '제주 마을의 초분'을 그리지 않는다.
     사진이 현재 전시·행사가 아니면 캡션에 **촬영 연도와 "자료 사진"**을 적고, 다른 전시 현수막 등이 보이면 그 사실도 적는다.
     어느 관(본관·분관)인지 기사에 없으면 건물 사진을 쓰지 않는다. 찾는 법: Commons 검색 API(`commons.wikimedia.org/w/api.php?action=query&list=search&srnamespace=6&srsearch=…`) →
     `prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=1280` 으로 라이선스·작가·촬영일·1280px 썸네일(`thumb.wikimedia.org/…`) 확인. User-Agent 에 저장소 주소를 넣고, 429 가 나면 10초 넘게 쉬었다 다시.
     **근현대 작가(유영국 1916~2002, 서세옥 1929~2020 등)의 작품은 보호기간 중**이라 쓰지 않는다.
   - 표기: `<figure class="photo" data-card-cap="한 줄 설명"><img src="URL" data-remote="URL" alt="…"><figcaption class="credit"><a href="파일 페이지">작가 · 라이선스 · Wikimedia Commons</a></figcaption></figure>`.
     push 하면 Actions(`localize_images.py`)가 저장소로 내려받는다. Commons 원본이 크면 `…/thumb/…/1280px-…` 형식 썸네일 URL 을 쓴다.
   - `check_cards.py` 는 Commons 크레디트에 라이선스 표기(CC BY·CC0·퍼블릭 도메인)가 없으면 FAIL.
2. **② AI 일러스트** (`.cn` 안 `<p class="cn-img">영문 장면</p>`) — 실제 이미지가 없는 **생활·문화·여행·액티비티·음악·과학(개념도)** 카드에 넣는다.
   - **반드시 ③ 대체 그림(`cn-v`·도표·정보 그림)도 함께 둔다.** 이미지는 push 뒤 Actions 가 만들고, 만들기 전·실패 시엔 대체 그림이 나온다(1단계 검사도 대체 그림으로 통과).
   - **나라·건축 양식을 분명히 쓴다**(2026-10-21: "curved tiled roof" 만 쓴 한국 시골집이 일본식 주택으로 그려졌다 → "Korean hanok, giwa roof, not Japanese architecture"). 생성된 그림은 push 뒤 직접 열어 확인하고, 어긋나면 `cn-gen` img 를 지우고 장면 문장을 고쳐 다시 push 한다.
   - 장면만 쓴다: 장소·사물·계절감·분위기. **작품·포스터·앨범 재현, 실존 인물, 실제 사건 장면 금지.** 사건·정치·재난·스포츠는 만들지 않는다(스크립트가 한 번 더 거른다).
   - **시안**: 브리프를 고치지 않고 그림만 보고 싶으면 같은 이름의 사본을 `drafts/` 에 두고 `cn-img` 를 넣어 push → `img/gen/YYYY-MM/drafts-<브리프>/NN.jpg` (앱·manifest 에는 안 나온다).
   - 생성된 다음 날 세션은 `img/gen/…` 이미지를 열어 글자·인물·작품 재현이 없는지 확인한다. 문제가 있으면 `cn-gen` img 를 지우고 장면 문장을 고쳐 push(다시 만든다).
3. **③ 개념도·도표·정보 그림** — 사건·정치·숫자 카드의 기본이자 ①②의 대체. 위 '카드 이미지·그림 개선 규칙'대로 그린다(점+글자 나열 금지, 값을 그림으로 — 예: 178점 중 15점은 점 178개 중 15개 강조).

#### 음악 브리프 — 이번 주 플레이리스트 (2026-10-21 개편, 사용자 결정) — **2026-10-24 폐지**

#### 음악 브리프 — 음원·주요 구절 (2026-10-21 검토)

- **K-POP·팝 음원 클립은 넣지 않는다.** 곡(작사·작곡)과 음반(제작사·실연자) 권리가 모두 살아 있고, 한국 저작권법에는 "몇 초 이하면 괜찮다"는 규정이 없다. 인스타 API 로 올리면 음원 탐지로 음소거·삭제될 수 있다.

**① 앱 — '들어 보기' 구간 (`figure.listen`, 음악 브리프 본문)**

- 음원 탐지 오탐으로 음소거될 수 있다 — 그러면 그 곡은 다음부터 쓰지 않는다.
- 가사 인용도 하지 않는다(짧아도 저작물).

#### 카드 검토 하네스 — 2단계 최종 확인 (2026-10-18~, 건너뛰지 말 것)

브리프 검토 하네스(체크리스트 1~16)를 통과한 뒤, **push 전에** 인스타 카드를 따로 두 단계로 검토한다. 카드는 브리프와 다른 매체(한 장에 그림+짧은 글)라 브리프 검토만으로는 못 잡는 문제가 있다.
대상: 메인 + 그날 서브 브리프 둘 다. 어느 단계든 FAIL 이면 **고친 뒤 1단계부터 다시** 돈다(최대 3회. 3회째에도 FAIL 이면 그 카드의 그림을 빼고 정보 시트로 두되 보고에 적는다).

**1단계 — 규칙 검사(기계)**
```bash
python3 tools/check_cards.py YYYY-MM-DD_science-brief.html     # FAIL 있으면 종료 코드 1
node tools/render_cards.js YYYY-MM-DD_science-brief.html /tmp/card-review/YYYY-MM-DD_science-brief   # 1080×1350 PNG, Actions 와 같은 렌더러
```
- 검사 항목: `cn-t` 2줄·줄 길이 · `cn-s` 70~100자·해요체 · 분류어 `.topic` 금지 · 그림 재료 유무(서브는 개념도·도표·이미지) ·
  **큰 숫자-제목 중복** · **카드용 숫자가 같은 카드 본문·스펙 표에 있는지** · `figure.photo` 호스트·크레디트·`data-card-cap` · `cn-v` 형식 · 같은 구도 반복(WARN).
- `render_cards.js` 는 렌더한 뒤 **넘침 검사**도 한다 — 카드 안의 글자·그림이 4:5 카드 밖으로 나가거나 잘리면 `FAIL 넘침` 을 찍고 종료 코드 1.
  (도입 첫날 10/17 메인 표지에서 계정 줄이 카드 밖으로 밀려난 기존 버그를 잡았다 → 표지 재료가 많은 날은 렌더러가 자동으로 촘촘한 배치를 쓴다.)
- WARN 은 2단계에서 눈으로 판단한다.

**2단계 — 시각 검토(독립 에이전트, 렌더된 PNG 를 직접 본다)**
작성 세션과 분리된 서브에이전트에 PNG 폴더와 브리프 HTML 경로를 주고 "통과시키는 게 아니라 문제를 찾는 것"이라고 지시한다. 카드마다 아래를 PASS/FAIL 로 판정하고, FAIL 은 고칠 문장·그림을 구체적으로 적게 한다.

| 축 | 질문 (하나라도 아니면 FAIL) |
|---|---|
| **규칙** | 글자 타일이 없는가 · 큰 숫자·그림이 제목과 같은 말을 반복하지 않는가 · `.topic` 이 그 카드만의 핵심어인가 · 같은 구도가 두 번 나오지 않는가 · 이미지 크레디트가 붙어 있는가 |
| **전문성** | 개념도가 **물리적·논리적으로 맞는가**(위치 관계·방향·인과) · 용어가 정확한가(규산염≠실리카, 심의≠의결) · 출처에 없는 값·과장이 그림에 들어가지 않았는가 · 개념도/계획 표시가 있는가 · 그림이 "왜·어떻게"를 보여 주는가(동그라미+글자 나열 ✗) |
| **가독성** | 폰에서(카드 폭 약 390px) 그림 속 글자가 읽히는가 · 글자·도형이 겹치거나 잘리지 않는가(번호 배지·쪽수 칩 포함) · 3초 안에 핵심이 들어오는가 · 그림과 제목이 같은 이야기인가 · 이미지 위 글자가 그림을 가리지 않는가 |
| **흐름** | 표지→카드→출처 순서로 넘겼을 때 이야기가 이어지는가 · 표지 목록이 카드 제목과 맞는가 · 마지막 장에 출처·이미지 크레디트가 있는가 |

- 2단계 에이전트에게도 **Firecrawl 금지**를 넘긴다. 사실 확인이 필요하면 브리프 카드 본문·출처 링크로 대조한다.
- 작성 환경에서 ESA 이미지가 막히면 렌더러가 "이미지 자리" 안내 그림을 넣는다 — 이 경우 2단계는 이미지 자리 배치만 보고, 실제 이미지는 push 뒤 Actions 가 구운 `cards/…/` JPG 로 다음 세션이 확인한다.
- 2단계를 통과하면 판정 요약(카드별 4축·고친 내용·반복 횟수)을 `/tmp/card-review/<브리프 이름>.stage2.md` 에 쓴다. **실제로 통과했을 때만** 쓴다.
- **push 관문(자동 강제)** — `.claude/settings.json` 의 PreToolUse 훅이 `git push` 마다 `tools/prepush_gate.py` 를 부른다.
  오늘·어제(KST) 브리프가 origin/main 과 다르면 1단계를 직접 다시 돌리고, 2단계 기록이 **있고 브리프보다 나중인지** 확인한다. 아니면 push 차단(이유가 메시지로 온다).
  검토 뒤 브리프를 고쳤다면 다시 검토해야 통과한다. 우회 금지(훅 끄기·기록 위조). 3회째 FAIL 인 카드는 그림 재료를 빼고 기록·보고에 적은 뒤 발행.
- 마무리 보고에 **1단계 FAIL/WARN 수, 2단계에서 고친 카드와 이유, 반복 횟수**를 적는다.

### 오디오 — 낭독 원고 + 자동 MP3 (2026.10.11~)

카드를 귀로도 듣게 한다. **원고는 브리프 작성 때 쓰고, 음성은 GitHub Actions 가 만든다.**
작성 환경(클라우드)에서는 TTS 서버가 네트워크 정책으로 차단되고, 오프라인 무료 음성은 품질이 낮아 쓰지 않는다.

- **원고 위치**: `</header>` 바로 뒤 `<details class="audio-script"><summary>🎧 낭독 원고 보기</summary><p>…</p></details>`.
  문단 하나가 `<p>` 하나. JS 없음 — 듣기 어려운 독자를 위한 대본 역할도 한다.
- **대상과 분량** (공백 제외 글자 수 · 대략 1분 ≈ 330자)

  | 브리프 | 분량 | 형식 |
  |---|---|---|
  | 메인 daily | 1,000~1,800자 (3~5분) | 카드 순서대로 한 문단씩 → **서울 날씨** → 클로징 |
  | ai · sports · culture · music | 700~1,300자 (2~4분) | 항목마다 핵심 + 디테일 포인트 한 줄 |
  | science 롱리드 | 1,300~2,000자 (4~6분) | 카드 흐름을 이야기처럼 이어서 |
  | **travel · activity** | **230~320자 (릴스 30초대, 2026-10-23~)** | **카드마다 한 문단(2026-10-23~ 릴스 정렬)** · **"이번 주 추천" 소개만** — 이름과 한 줄 매력. 가격·주소·기간은 읽지 않고 "자세한 정보는 카드에서" |

- **원고 쓰는 법**
  - **2026-10-23~ 릴스는 첫 문단을 뺀다** → 첫 문단은 날짜 한 줄("M월 D일 X요일, ○○ 브리프입니다." + 한 줄 소개)만 두고, **훅은 카드 1 문단의 첫 문장**에 쓴다(예: "이번 주말, 전국 떡볶이 37곳이 대구에 모입니다."). 질문이나 숫자로 시작하고, 날짜·인사·"소개합니다"로 시작하지 않는다. 카드 하나 = 문단 하나, 카드당 1~2문장. 릴스는 1.2배속(`make_reel.js` `SPEED`)·문단 쉼 0.35초라 원고 250자 ≈ 35초.
  - (2026-10-19~10-22) 오프닝은 **훅 한 문장 + 날짜**: 첫 문장은 첫 카드의 핵심을 숫자와 함께 한 문장으로(예: "중국이 AI 핵심 기술 23개의 수출을 막겠다고 나섰습니다."),
    이어서 "M월 D일 X요일, ○○ 브리프입니다." → 본문 → 클로징. 훅 문장의 사실·숫자도 첫 카드 본문·스펙 표에 있는 것만.
    이유: 릴스 3편(10/17~19)이 길이와 상관없이 **평균 시청 2초·건너뛰기 85~91%** — 인사로 시작하는 첫 2초에 다 넘겼다.
  - **첫 카드 = 그날 가장 센 항목**(서브 브리프 포함). 릴스 첫 장면(훅 카드)이 첫 카드의 `cn-t`·`cn-num` 을 쓴다.
  - 괄호·출처 표기·"매체별 불일치" 같은 말은 빼고, 출처는 단일 출처 수치에만 "○○에 따르면".
  - 숫자는 귀에 맞게 반올림만(1,342.8원 → 1,340원대). **엇갈리는 수치는 "30여 명", "여러 명"으로.**
  - '마케터의 시선'은 읽지 않는다. 듣는 사람에게 쓸모 있는 한 줄은 카드에 있는 값으로만.
- **생성 흐름**: push → Actions `make_audio.py` 가 원고를 문단별로 Google Cloud TTS(Chirp 3 HD, 기본 `ko-KR-Chirp3-HD-Kore`)로
  합성 → 48kbps 모노 MP3 → **레포 `audio/YYYY-MM/YYYY-MM-DD_<type>.mp3`** 에 저장 →
  `</header>` 뒤에 `<div class="audio-player"><audio controls preload="none" src="audio/…">`(상대경로) 삽입 후 MP3와 함께 커밋(`[skip ci]`).
- **실패 원칙**: 키(`GOOGLE_TTS_API_KEY` 시크릿)가 없거나 합성·업로드가 실패하면 그 브리프는 건드리지 않는다 →
  재생기 없이 원고만 보인다. 빌드는 실패하지 않는다. 이미 재생기가 있는 브리프는 다시 만들지 않는다
  (다시 만들려면 `audio-player` div 를 지우고 push). 키가 없어도 Releases→레포 마이그레이션은 수행한다.
- **메인 원고의 날씨**: 방송 뉴스처럼 **마지막(클로징 직전)** 에 "끝으로 오늘 서울 날씨입니다." 한 문단. 페이지 상단 날씨 한 줄과 같은 내용.
- **MP3 는 레포 `audio/` 에 둔다 (2026-10-13 변경).** 처음엔 Releases 에 올렸지만, Releases 파일은
  `application/octet-stream`·다운로드(attachment)로 내려와 **iPhone Safari 에서 재생되지 않았다.** 레포 파일은 GitHub Pages 가
  `audio/mpeg` 로 서빙한다. Releases 주소가 남은 예전 재생기는 Actions 가 실행될 때 자동으로 `audio/` 로 옮기고 src 를 고친다.
  하루 약 2~3MB(메인+서브) — 레포가 1GB 에 가까워지면 오래된 달의 `audio/YYYY-MM/` 을 정리한다.
  브리프를 월별 폴더로 옮길 때는 상대경로 src 가 깨지므로 `audio/` 경로를 함께 확인할 것.
- 목소리·속도는 워크플로 env `TTS_VOICE`·`TTS_RATE` 로 바꾼다.

### 서울 날씨 한 줄 — 메인 브리프 상단 (2026.10.11~)

비 소식이 있으면 우산을 챙기게 하는 한 줄. 메인 브리프 header 안, `.masthead-meta` 와 `.lede` 사이에 둔다.

- **출처**: 오늘 아침(또는 전날 저녁) 발행된 **날씨 기사 본문**(뉴스1·뉴시스·YTN 등 "오늘 날씨" 기사)을 WebFetch로 열어
  **서울** 최저·최고기온과 비·눈 소식(시간대)을 확인한다. 서울 값이 없으면 수도권 표기를 그대로 쓰고, 둘 다 없으면 한 줄을 넣지 않는다.
- **형식**: `☀/⛅/☂ 서울 · 최저 N° 최고 N° · 비 소식(있으면 시간대)` + 비가 있으면 **"우산 챙기세요"** + `⚠ 변동 가능` + 출처 링크.
- 기사에 없는 값(강수확률·미세먼지 등)은 넣지 않는다.

```html
<p class="weather">☂ 서울 · 최저 14° 최고 21° · 오후부터 비 — <strong>우산 챙기세요</strong>
  <span class="wx-note">⚠ 변동 가능 · <a href="기사 URL">뉴스1 06:00</a></span></p>
```

### 카드 넘겨보기 · 인스타용 이미지 (2026.10.17~)

브리프 한 편을 **인스타 비율(4:5) 카드**로 다시 그린다. 위 절반은 그림, 경계에 번호 배지, 아래는 출처·분야·굵은 제목 2줄·3줄 요약.
**보도사진은 여전히 쓰지 않는다.** 위쪽 그림은 도표·단계 표시·인용·**정보 그림(지도·달력·큰 숫자)**·**AI 일러스트** 순으로 채운다.
**한자 타일은 쓰지 않는다**(2026-10-17 폐지 — 매번 글자 하나라 형식적으로 보였다). 브리프 본문의 `.hanja` 배경글자는 그대로 둔다.

- **렌더러**: `app/cards.html?f=<브리프 파일명>` — 브리프 HTML 을 읽어 카드를 만든다. 앱의 오늘 카드 **「카드」** 버튼이 이걸 리더로 연다.
- **카드 재료** (우선순위 순)

  | 자리 | 1순위 | 없으면 |
  |---|---|---|
  | 제목 | `.cn .cn-t` (`<br>` 로 2줄) | `h2` 의 " — " 앞부분 |
  | 요약 | `.cn .cn-s` | 요약 첫 문단에서 괄호를 빼고 100자 안쪽 문장까지 |
  | 그림 | `.cn svg.cn-v` | 카드의 `figure.chart` → **정보 그림**(`.cn-place`·`.cn-when`·`.cn-num`) → **AI 일러스트**(`.cn img.cn-gen`) → 분야 글자 타일 |
  | 출처·분야 | `a.source` 매체명(최대 2개) · `.topic` | — |

- **메인·서브 모두 카드마다 `.cn` 블록을 쓴다** (`</article>` 바로 앞, 2026-10-17 확정). 없으면 위 대체 규칙으로 자동 생성되지만 그림이 약해진다.
  - `cn-t` 짧은 제목 2줄(`<br>`) · `cn-s` 해요체 2~3문장 70~100자.
  - 그림 필드를 카드 성격에 맞게 **하나 이상**: 숫자 `cn-num` · 변화 `cn-shift` · 관계 `cn-link` · 경기 `cn-score` · 장소·기간 `cn-place`·`cn-when` (아래 '정보 그림' 표). 카드에 도표가 있으면 생략 가능.
  - **메인은 '맥락 읽기' 카드를 뺀 모든 카드에 핵심 숫자 `cn-num` 하나를 꼭 적는다** — 금요일 '이번 주 숫자' 재료. 사건·재난 카드는 숫자 대신 `cn-v` 시간 순서 그림.
  - 모든 값은 같은 카드 본문·스펙 표에 있는 것만(체크리스트 16번).
  ```html
  <div class="cn" hidden>
    <p class="cn-t">코스피 하루 만에 반등,<br>5,668로 마감</p>
    <p class="cn-s">16일 코스피가 2.05% 올라 8거래일 만에 상승 마감했어요. …</p>
    <svg class="cn-v" viewBox="0 0 400 220" role="img" aria-label="…">…</svg>   <!-- 선택 -->
  </div>
  ```
  - `.cn-t`: 2줄, 줄마다 14자 안팎. `.cn-s`: **해요체** 2~3문장, 70~100자(카드에서 3줄까지 보인다). 사실·숫자는 카드 본문·스펙 표에 있는 것만.
  - `svg.cn-v` 는 카드에 `figure.chart` 가 없을 때 쓴다(있으면 생략 — 도표가 자동으로 올라간다). viewBox `0 0 400 220` 고정.
    클래스 어휘: 단계 `cn-on`·`cn-off`·`cn-line`·`cn-line-off`·`cn-ring` / 글자 `cn-big`(16)·`cn-small`(13)·`cn-dim` /
    인용 `cn-q`·`cn-qm` / 막대·선 `cn-b1`·`cn-b2`·`cn-ln`·`cn-dot`·`cn-grid`·`cn-ax`·`cn-val`·`cn-cat`. 색은 렌더러가 브리프 액센트·계열색으로 칠한다.
    예시는 `2026-10-17_daily-brief.html` 의 `.cn` 블록.
  - 재난·참사·사건 카드는 시간 순서·절차 단계 같은 담담한 그림만. 인용 그림은 원문 그대로.
- **정보 그림 (2026-10-17~)** — `.cn` 안에 한 줄씩 적으면 렌더러가 그린다. **값은 카드 본문·스펙 표에 있는 것만.**
  **원칙: 카드마다 큰 요소 하나 + 보조 한두 줄.** 작은 글씨를 여러 줄 늘어놓지 않는다(한눈에 안 들어온다).

  | 필드 | 형식 | 그림 |
  |---|---|---|
  | `cn-fixtures` | `PSG\|토 23:00\|낭트 / 맨시티\|일 새벽 1:30\|아스널` (최대 6경기) | 경기 일정판 — 팀 · **한국시간 킥오프 알약** · 팀, 맨 위 '킥오프 · 한국시간' 고정(2026-10-24~, 축구 프리뷰). 시각은 요일과 함께 9자 안쪽 |
  | `cn-score` | `한국\|2\|0\|우즈베키스탄` | 스코어보드 (`data-best="4"` 면 시리즈 승리 점 — 카드에 시리즈 방식이 있을 때만) |
  | `cn-link` | `엔비디아\|인수·투자 협상\|리플렉션 AI` | 관계도 (주체 → 관계 → 대상) + `cn-num` 하나를 크게 |
  | `cn-shift` | `새 규제\|손해배상 책임\|개발사가 진다` | 전환 그림 (이전 취소선 → 이후) + `cn-num` 타일 최대 2개 |
  | `cn-steps` | `1단계 여행유의\|…\|4단계 여행금지` + `data-now="3"` | 단계 목록(장소가 있으면 지도 옆 세로 목록) |
  | `cn-bars` | `서울:65\|2위 울산:47` | 미니 막대(0에서 시작, 최대 4개) + `cn-num` 하나 |
  | `cn-place` | `진주` · `서울 마포` · `설악 9/28@속초` · `사우디아라비아` | 국내 지도 핀(시·군·구) / 나라 지도 강조. 쉼표로 최대 5곳, `라벨@지명` 으로 핀 이름 지정 |
  | `cn-when` | `10/17~10/25` · `~10/18`(+`data-label="폐막"`) | 같은 달 기간은 달력, 끝날짜는 날짜 칩 |
  | `cn-num` | `120곳\|동네 빵집` (최대 2개) | 큰 숫자 |
  | `cn-note` | `17일(토) 20:00 / 수상 불꽃놀이` | 보조 한두 줄. **줄 나눔은 앞뒤 공백 있는 " / "** (날짜 "10/6" 은 안 나뉜다) |

  - 우선순위: scores → fixtures → score → link → shift → steps → bars → 장소+숫자/날짜 조합 → 기간 달력 → 숫자 → 장소만.
  - **공식 제도의 단계 이름**(여행경보 1~4단계 등)은 카드에 현재 단계가 적혀 있으면 나머지 단계 이름을 써도 된다. 그 밖의 값은 카드에 있어야 한다.
  - 지도: `app/geo/kr.json`(윤곽 Natural Earth 1:10m 퍼블릭 도메인 · 지명 945개 KOSTAT 2018 시군구 경계 중심점, southkorea-maps 자유 이용),
    `app/geo/world.json`(Natural Earth 1:50m 나라 경계 · 한국어 나라 이름 170개, 필요할 때만 불러온다). 핀은 시·군·구 중심점이며 행사장 위치가 아니다.
    사전에 없는 이름은 그리지 않는다(해외 도시는 아직 없음 — 나라 이름을 쓴다).
- **브리프별 카드 그림 규칙 (2026-10-17 확정)**

  | 브리프 | 기본 그림 | AI 일러스트 |
  |---|---|---|
  | 메인 | 도표 · 단계(`cn-v`) · 인용 · 정보 그림 — 사건 타임라인은 **실제 시각에 비례한 간격**(축척 밖 구간은 점선), 판결은 형량 막대 | 생활·경제·문화 카드 (사건·정치·재난·안보 제외). `cn-num` 도 남긴다 — '이번 주 숫자' 묶음은 AI 대신 숫자 그림을 쓴다 |

### 앱 (PWA) — `app/` (2026.10.13~)

브리프를 앱처럼 쓰는 화면. 주소 `…/Daily-Card-News/app/` 를 iPhone Safari 에서 열고 **공유 → 홈 화면에 추가**.

- **첫 주소 `…/Daily-Card-News/` 는 앱으로 넘어간다**(2026-10-22 — 예전 목록 페이지 폐지, 날짜별 목록은 아카이브 탭). 루트 `index.html` 은 넘김 페이지뿐이다.
- **관리자 기기**(카드 일괄 저장 패널): 앱 주소(`…/Daily-Card-News/?admin=1`, `…/app/?admin=1`, `…/app/cards.html?…&admin=1` 어느 것이든)로 한 번 열면 그 브라우저에 기억된다. 끄기는 `?admin=0`. 홈 화면 앱은 Safari 와 저장소가 따로라 홈 화면 앱 안에서는 따로 켜야 한다. 보안 장치가 아니라 화면 정리용(카드 JPG 는 공개 주소).
- **넓은 화면**(2026-10-22): 폭 900px 이상(PC·태블릿 가로)은 브리프 칸·목록을 **2열**(3열은 썸네일이 작아 쓰지 않는다), 1400px 이상은 폭만 넓힌다. 휴대폰 화면은 1열.
- **다크 테마**(2026-10-22): 앱 셸은 어두운 배경(`--bg #111113`·`--card #1c1c20`)에 칸마다 진한 테두리(`--edge`). 액센트는 밝힌 색(`--act`)으로 글자·윗선을 칠한다. 리더 안 브리프 본문·카드 화면은 원래의 밝은 화면 그대로.
- **오늘 브리프 칸 = 피드형**(2026-10-22 사용자 결정): 상자 없이 굵은 구분선, **분야 배지 → 헤드라인(›, 눌러도 읽기) → 카드뉴스 띠(누른 장부터 카드 보기 — `cards.html?s=N`) → 읽기·듣기** 순서. '카드' 버튼은 카드 띠가 없을 때(이미지 굽기 전·어제 칸)만 보인다. 관리자 기기는 카드 띠를 눌러 연 카드 화면 아래에서 그대로 일괄 저장. 리드·핵심 3줄·N Picks 는 카드와 겹쳐 뺐다(어제·지난 브리프 칸은 작은 상자 그대로).
- **카드 썸네일**(2026-10-22): 오늘 탭 브리프 칸에 Actions 가 구운 카드 JPG(카드 1장부터 최대 8장)를 4:5 전체로 크게 가로 띠에 놓아 옆으로 넘겨 본다. 누르면 카드 보기. 이미지가 아직 없으면 띠를 숨긴다.
- **오늘 탭**: 최신 날짜의 메인·서브 카드(제목·리드), 메인 브리프의 서울 날씨 한 줄, **"오늘 브리프 듣기"** — 메인 → 서브 오디오 연속 재생(잠금화면 제어).
- **아카이브 탭**: 분야별 칩 + 월별 목록. **파운드리는 앱에 나오지 않는다**(`EXCLUDE`).
- 브리프는 앱 안 리더(iframe)로 열린다 — 홈 화면 앱에는 브라우저 뒤로가기 버튼이 없어서.
- 데이터는 `manifest.json` + 각 브리프 HTML 에서 읽는다(h1·.lede·.count·.weather·.audio-player). **브리프 구조를 바꾸면 앱도 확인할 것.**
- 파일: `app/index.html`(앱 전체) · `app/cards.html`(카드 넘겨보기) · `app/geo/kr.json`·`world.json`(지도·지명 좌표) · `app/app.webmanifest` · `app/icons/` · 루트 `sw.js`(서비스 워커 — 루트에 있어야 브리프까지 오프라인 저장).
  서비스 워커는 네트워크 우선, 오프라인일 때만 저장본. MP3·외부 폰트는 건드리지 않는다. 앱을 고치면 `sw.js` 의 `VERSION` 을 올린다.
- **"JS 0줄" 원칙은 브리프 HTML 에만 적용**한다. 앱 셸(`app/`, `sw.js`, 기존 `index.html`)은 예외. 데일리 자동 작성은 `app/`·`sw.js` 를 건드리지 않는다.
