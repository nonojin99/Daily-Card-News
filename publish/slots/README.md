# 시간대 게시 (2026-10-26~)

릴스를 하루 여러 시간대에 나눠 올린다 — 워크플로 `Publish scheduled reels`(`.github/workflows/publish-evening.yml`), 스크립트 `.github/scripts/publish_slots.py`.

| 시간대 | KST | 쓰임 |
|---|---|---|
| `0730` | 출근 | 전날 밤 루틴이 만든 릴스(야구 나이트 등)·미리 검수가 끝난 것 |
| `1210` | 점심 | 06:00 루틴의 깊게 파는 릴스 |
| `1840` | 퇴근 | 〃 |
| `2107` | 저녁 | 〃 · 코너 릴스(예전 `publish/evening/`) |

파일 이름: **`<게시 날짜>_<HHMM>_<이름>.json`**, 내용은 `publish/request.json` 과 같은 `{"requests":[…], "note":"…"}`.

```json
{"requests": [
  {"kind":"reel","media":"reels/2026-10/2026-10-27_daily_c3.mp4","caption":"captions/2026-10-27_daily_c3_reel.txt","dry_run":"false","is_ai":"true","review":"human"}
], "note": "10/27 깊게 파는 릴스 — 카드 3 (점수 86)"}
```

- **시간대 배정**: 그날 고른 릴스를 점수 순으로 놓고, 시간대 순서 `1210 → 1840 → 2107` 을 **날짜마다 한 칸씩 돌려서** 배정한다
  (`(그해의 몇째 날) % 3` 만큼 왼쪽으로 회전) — 점수 높은 항목이 늘 같은 시간대에 가면 시간대 효과와 점수 효과가 섞여 판정할 수 없다.
- 놓친 항목(검수 대기였다가 나중에 승인, 예약 실행이 건너뛰어짐)은 그날 다음 시간대 실행이 **한 번에 1건씩** 따라잡는다. 날짜가 지나면 올리지 않는다.
- 같은 캡션이 최근 게시물에 있으면 컨테이너를 만들기 전에 건너뛴다 — 몇 번 실행돼도 중복 게시되지 않는다.
- 같은 계정 릴스는 시간대마다 1편이 원칙(코너 릴스와 깊게 파는 릴스가 겹치면 하나를 다음 시간대로).
